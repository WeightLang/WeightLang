# migrate-to-weightlang

交付能在原项目中继续开发、训练和推理的 WeightLang 项目，以及可读的 `.wgt` 和验证证据。
用户只要架构时不要求旧权重；需要保留权重时再交付权重转换步骤和对比结果。

## 先明确“迁移到”的含义

- “把这个项目迁移到 WeightLang”是把当前或指定的模型开发项目改用 WeightLang，
  默认在原仓库、当前分支实施。WeightLang 是目标技术栈，不是产物存放目录。
- 区分**待迁移项目**与**WeightLang 编译器仓库**。后者用于查实现、运行工具及必要的语言扩展；
  除非用户明确要求新增官方示例、教程或另建目录，不把原项目复制到其 `examples/`、
  `packages/` 等目录，也不以一个旁路演示项目代替原项目迁移。
- 迁移必须接入原项目的实际入口、依赖配置、训练/推理流程和文档，使 WGT 成为所迁模型的
  可维护架构来源。仅导出一批叶子算子、保留原 Python 模型为唯一主入口，属于部分转换，
  不能汇报为项目迁移完成。
- “只迁架构，模型可以重新训练”表示无需寻找或迁移旧检查点；允许初始化参数用于等价性
  验证，并保留可重训能力，不表示授权启动长时间训练。

## 先确定迁移对象

从当前仓库、用户路径和已连接来源定位模型定义、forward、配置、权重、预处理与调用入口。
分清架构源码、完整模型目录、裸检查点、适配器及普通应用代码。
优先从现有文件确认输入输出、目标设备和验收方式；仅在缺失信息会改变结果时询问。
普通项目迁移模型计算，保留必要的预处理、I/O、调度等宿主代码；不要把任意业务逻辑包装成
“纯权重实现”。核心架构因语言缺口仍留在原框架时，明确记录尚未完成的部分，不能自行把
“项目迁移”降格为“组件包装 + 原模型宿主”的示例并宣布完成。

先读待迁移项目的 AGENTS.md 和现有项目约定，再定位可用的 WeightLang 源码与实际编译器，
读取其存储及语言文档；不要因为定位到了编译器仓库就把工作目标切换过去。
优先使用当前 WeightLang checkout；技能随仓库分发在 `.agents/skills/migrate-to-weightlang/`，
全局安装时从用户指定路径或当前工作区定位仓库，不假定固定的个人目录。
编写或修改 WGT 时使用已安装的 `wgt-development` 技能；找不到时以当前实现和中文参考为准。
只采用当前实现支持的语法；核对版本，不把本地尚未发布的功能说成发布版能力。

## 按证据选择转换路线

详细命令、权重映射和验收方法见 [迁移路线](references/migration.md)，
项目迁移先读其中“项目接入”，再按输入类型读取相应部分。

- 已有 WeightLang 模型：重写为 `wgt 0.5`；保留权重时显式映射到原生模型格式并验证。
- Python 模型：当前没有 Python 导入器；根据真实结构手写受支持的原生 WGT，再单独映射参数。
- 任意 PyTorch/其他框架模型：依据真实 forward 手写等价 WGT，逐项验证算子语义和参数布局。
- 只有检查点：先读取结构/张量信息；没有前向语义时不能声称恢复了可执行模型。

迁移前列出会影响等价性的缺口：张量轴序、dtype、激活、归一化、掩码、位置编码、
参数共享、循环状态和预处理。匹配名字或形状不足以证明语义一致。
未支持部分给出具体位置和可行路径；不要悄悄换成近似结构、丢弃权重、重新训练或随机补齐。
需要扩展语言时按任务范围实施最小可验证扩展，并同步语言参考与 wgt-development；
大范围新后端或训练任务先明确影响，同时继续可独立完成的迁移工作。

## 完成迁移

1. 在待迁移项目内生成 WGT 源码并改接实际入口；保留原权重、当前分支和无关修改。
   原实现可作为对照基线，但不能以“不改原项目”为默认目标。说明轴含义、形状变化、共享关系及训练状态。
2. 用 `weightc check SOURCE` 验证结构，再用 `weightc compile SOURCE -o EXECUTABLE` 编译。
   检查和编译不执行 main；训练和保存必须在实际运行时显式调用。
3. 迁移权重时保存来源哈希、显式张量映射和必要布局/dtype 变换，验证键、形状及数值。
   用受支持的保存接口生成新模型并重载，不能直接改 manifest 绑定的权重文件。
4. 用相同输入与预处理比较原模型和重载后的模型。先对齐 eval 模式、dtype 和设备，
   再比较形状、有限性、最大绝对误差与明确容差；选择能覆盖分支、掩码或序列状态的用例。
   项目需要保持训练能力时，再验证梯度、冻结行为和最小优化步骤；这不等于启动完整重训。
   推理迁移不额外启动训练。
5. 有差异时用 `print`/`metric` 和最小输入定位，修复后重跑相关用例。
   通过原项目入口验证实际构建、加载、推理和按需训练/保存路径，更新原项目文档。
   按范围输出架构、模型、转换脚本、对比报告和运行命令，并列清未支持或未验证部分。

## 保存与交付边界

- 以下路径均相对**待迁移项目根目录**，不是 WeightLang 编译器仓库。
  完整模型保存在 `weights/<model>/`，实验基线、候选与报告保存在 `weights/<experiment>/`。
  不覆盖原模型或保留目录；不得默认开启 --force。
- 小临时文件用 `/tmp/weightlang/`；大权重、数据和构建中间物用磁盘目录或 `.cache/weightlang/`。
  预计超过 100 MB 前直接检查目标目录、剩余空间、实际挂载与冗余内容，不依赖专门技能。
  清理本次一次性文件，不清理保留模型。
- 汇报精确区分：结构描述、可执行结构、实际权重已迁移、样本对齐已通过、训练能力已验证。
  检查点元数据不证明训练来源；输出一致性不证明完整任务质量或所有输入上的等价性。
