# Storage

- Follow [docs/storage.md](docs/storage.md). Keep complete models in `weights/<model>/` and retained experiment baselines, candidates and reports in `weights/<experiment>/`; never overwrite without explicit `--force` or treat them as cache.
- Small temporary files belong in `/tmp/weightlang/` (platform equivalent elsewhere). Large weights, datasets, downloads and build intermediates use disk-backed project paths or `.cache/weightlang/`, never tmpfs; check space and the actual mount before large writes. `target/` is only a Rust compiler cache.
- Clean only task-created disposable files; preserve unrelated work and model outputs. Other projects use `/tmp/<project>/` and their own disk cache.

# Language changes

- The source language targets Rust edition 2024 for host integration and Rust API examples. For every public WGT language change, update [docs/reference.zh-CN.md](docs/reference.zh-CN.md), related topic docs and WGT skill references/examples in the same change. This includes parser/version rules, expressions, defaults, shape/dtype contracts, graph/loop/runtime behavior, training/import/freezing and `std/*.wgt` changes.
- Treat `crates/wgt-language/src/`, `language/primitive_specs.json`, `std/*.wgt` and relevant `crates/wgtime-core/` and service code as authoritative for implemented language and execution. Rust applications own data preparation, I/O, scheduling, service connection and training loops; WGT and `std/` focus on reusable model architecture and model-internal parameter/tensor flow, submodules, branching, loops and state, plus optional differentiable loss. The legacy general-purpose WGT host-script architecture is being retired: do not create new host-control scripts or document that architecture as a supported direction. Do not claim old implementations have been removed unless verified. Compiled forward and module imports are in implementation and have not yet been accepted; document them as pending verification, not supported capabilities. Document purpose, complete signatures, parameters/defaults, constraints, versions, limitations and valid examples. Distinguish definitions, initialized instances, trained weights, local implementation and released features; parsing alone does not prove execution support.
- Compare the reference against all `_stmt_*` handlers, operator sets/defaults and standard-library signatures. Parse complete examples locally, run focused behavior checks for semantic changes, verify links and run `git diff --check`. Report unverified items; no remote CI is required for documentation maintenance. Do this as part of the task, not with a background generator.

# WGT authoring

- The model source entrypoint must be named `model.wgt`. Put each independent model/example in its own directory (for example `examples/native_training/working_memory/model.wgt`); use directory names to distinguish models, never `main.wgt`, `train.wgt` or a feature-named entrypoint. Keep commands, links, test fixtures that load real examples, and relative data/output paths aligned when moving files. This source-entry convention does not rename artifact snapshots such as `source.wgt` or library modules under `std/`.

- For model authoring or language implementation, use `/home/lightjunction/.codex/skills/wgt-development/SKILL.md` when available. Keep its grammar and runnable examples aligned with the latest implemented language only; validate against the current parser/runtime, excluding historical syntax and unimplemented proposals.
- New or substantially changed WGT examples need meaningful comments explaining axis meanings, shape transitions, gate/reduction intent, independent versus shared loop weights and initialization/training state. Explain intent rather than narrating obvious lines.

# Architectural boundary

- Rust applications own data preparation, I/O, scheduling, service connection and training loops. WGT and `std/` focus on reusable model architecture and model-internal parameter/tensor flow, submodules, branching, loops and state, plus optional differentiable loss. The legacy general-purpose WGT host-script architecture is being retired; do not create new host-control scripts or present it as a supported direction. This does not assert that existing code has already been removed. Python sources, tests and packaging have been retired; do not restore Python entrypoints or implement native paths as Python callback wrappers. See docs/native-backend.md for the Rust model contract and docs/native-training.md for implementation status and remaining migration boundaries.
- Model definitions, service instances, trained weights and optimizer-bearing checkpoints are distinct. Parsing or loading a definition must not initialize service state, train, or create artifacts implicitly. Model execution and mutable state belong to the unique wgtime service.
- The current Rust model definition contract supports one f32 vector input; its definition entrances reject imports. Compiled forward and module imports remain in implementation and have not been accepted; do not claim them or multi-input, batch forward, cache or arbitrary dtype support until implementation and behavioral verification are complete.
- Do not add arbitrary Python execution to WGT model computation or Rust host paths as a shortcut.
