# 可执行机制原型：实际用途与能力边界

## 最合适的落地形式

当前字符串核心适合做一个“给例子，学转换，导出程序”的本地命令行工具。用户给若干输入→输出示例，程序在固定字符串操作语言内找一个一致的短程序；用户用额外样本验收后，把程序用于同一格式的批处理。推理阶段解释 JSON AST，无需远程大模型服务。此处是用途建议，不代表已部署或获得生产可靠性证明。

具体可用场景包括固定格式日志中的字段提取、CSV 单列清洗、邮箱或 URL 的局部文本提取、命名格式统一、电话字符串的字符清理和重新拼接。它学的是用户示例定义的字符串映射，不自动知道电话号码的真实性、URL 的完整标准语义或姓名的文化规则。文件名转换宜先输出改名预览，再由独立执行器应用；本原型不承担文件操作。

对 WeightLang 的可研究接口，是把学出的程序表示为可序列化的非张量 IR：基本操作、参数、串联和拼接，以及由外部评测记录的适用范围、反例和运行成本。这样可以研究“学出一段可运行代码”而不把所有能力都塞进连续权重。当前程序库命中只是复用已学完整程序，不能自动等同于子程序发明、跨领域抽象或不断变聪明。

## 这轮证据具体证明什么

字符串实验能检验：在预声明的有限操作语言、样例数量和搜索预算下，能否从示例学出可运行程序；程序在未参与搜索的样例上是否正确；行为去重、索引和库优先尝试会改变多少搜索开销。某些任务成功意味着其目标函数恰好可由当前基本操作表达；失败也可能是表达能力不足、预算不足或示例歧义。

独立的 CostTree 探针能检验：已提供信息性人工特征时，小型阈值程序可在真实表格数据上提供多高的分类准确率、花多少 CPU 时间。它是既有决策树方法，不能作为字符串核心或更广泛理论的因果证据。

## 现在不能声称

- 尚未证明“全新理论”、优于已有程序综合系统，或达到超智能、通用智能。
- 没有从原始图像、声音、开放自然语言中自动学习表示。
- 训练样例一致不等于语义正确；有限样例常同时支持多个互相冲突的程序。
- 观察数据中的预测关系不等于因果机制；没有干预实验就不能声称因果发现。
- 当前字符串 DSL 无通用循环、递归、条件推理或无界算法发现；搜索仍受组合爆炸限制。
- 库命中加速只有在计入发现成本、查找成本、失配和分布变化后，才可能形成净收益。
- 本次 CPU 可运行不代表所有规模都高效，也不代表击败 GPU 神经网络的吞吐量或能力。
- 缺少线上分布漂移、持续反馈、回滚、适用域识别和长期运行验证，不能称为生产系统。

## 最有意义的下一轮检验

固定一种真实工作流，收集按时间先后分割的转换任务和用户纠正记录；禁止同一格式近重复任务横跨库构建与测试。按“累计人类修正次数、最终正确率、从零开始的累计训练与推理 CPU 时间、峰值内存”衡量收益。只有在这样的累计账本上获益，才能说工具用过之后确实降低了后续工作的成本。
