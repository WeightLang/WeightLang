# 可执行机制学习研究报告

日期：2026 年 11 月 10 日  
状态：候选理论与可复现研究原型；已完成第一轮公开数据实验

## 结论

本研究提出一条面向低计算成本智能的路线：把经验变成可执行的小程序，在新任务中寻找、组合和修正这些程序，并把发现知识的成本与使用知识的成本一起记账。学习器通过离散搜索、比较、计数、字符串操作和索引工作，核心使用 Python 标准库，没有神经网络、反向传播或密集矩阵乘法。

原型已经完成实际学习与推理。公开字符串任务中，40 个任务经过 5 次划分，200 次任务划分评估中有 146 次通过全部留出样例，成功率为 73%。单次学习中位数为 1.565 毫秒，平均数为 37.892 毫秒；长尾任务显著增加平均成本。整个四模式字符串实验耗时 24.187 秒，进程峰值 RSS 为 20.125 MiB。

最重要的研究发现是负结果：完整程序缓存没有提高成功率，计入建库后的累计学习成本增加 5.13%；进一步复用程序片段后，成功率从 146/200 降到 144/200。当前结果支持低成本的特定任务程序学习，也揭示了“旧知识一旦拟合训练样例就优先接受”的错误。通用智能、超级智能以及自主持续增强，仍然是未达成的研究目标。

## 一 从计算本身出发

经典计算机执行的是有限的状态转移：读数据、比较、分支、修改状态、输出。矩阵和梯度是组织计算的一种方法；本研究考察另一种组织方式：直接学习执行步骤。应当比较的是学习到可靠技能所需的样本、搜索计算、执行计算和内存，而不是把某种数学记号本身当作智能或低效的来源。

一个例子是姓名顺序转换。给出若干“名字 姓氏”到“姓氏, 名字”的示例，学习器可以生成：

```text
concat(
    split(input, whitespace, 1),
    literal(", "),
    split(input, whitespace, 0)
)
```

随后面对新的姓名，它直接执行这段程序。速度来自任务已经被表达为几个必要操作。推理不再重新遍历训练样例，也不需要在每次调用时重新搜索程序。这里的能力边界同样具体：程序假定输入是两个用空白分隔的部分，复姓、多段姓名等情况需要额外证据与表达能力。

程序的基本原语也是先验。字符串分段、字符类别、大小写转换等含有人类对任务的知识；不能把人工设计的原语价值全部归功于学习器。

## 二 候选理论 以未来节省的计算检验知识

研究假说如下：

> 一项知识有计算价值，当它能够用较少的新证据，在未见任务上构造可靠的执行过程，并在预先规定的使用范围内抵偿其发现、验证、检索和维护成本。

这是假说与设计原则，不是智能的唯一数学定义。它提出三个需要分别测试的要求。

第一，知识应当能执行。记住一个答案只覆盖一个输入；学到一个程序可能覆盖一个输入族。程序也可以是比较树、有限状态机、提取器或受限制的组合表达式。

第二，知识应当带有证据。记录它在哪些输入上成功、在哪些反例上失败、依赖哪些格式假设。当前样例上的正确性是经验支持，只有形式化规格和相应证明才能提供更强保证。

第三，知识应当接受成本检验。一个复用组件可能缩短目标程序，也可能扩大分支数量、增加匹配成本，并让错误候选更早被接受。因此，程序库变大本身不是成功指标。

### 双账本的形式化

设任务序列为 T₁,…,Tₙ，当前知识库为 Mₜ，针对任务产生的程序为 pₜ，错误损失为 ℓₜ。一个候选研究目标是：

```text
min E[Σₜ (ℓₜ + λs Csearch,t + λv Cverify,t
                  + λe Cexecute,t + λm Cmemory,t)]
```

各项 λ 明确表达产品的资源偏好；它们不是自然常数。最好的准确率、最低延迟、最小内存未必由同一个系统实现，研究应报告这些维度的取舍。

“知识账本”记录程序结构、适用范围及反例；“计算账本”记录候选生成、验证、索引、复用和执行支出。当前实现记录了其中部分可观测量，尚未实现自动优化整个目标的策略。

在一个预先规定的任务范围内，设新增组件的发现成本为 D，验证与建索引成本为 V，每个任务的检索和维护成本为 a，平均节省的搜索成本为 s，共服务 K 个任务。其累计计算收益为：

```text
G(K) = K(s − a) − D − V
```

若 s > a，则收益转正所需任务数满足 K > (D + V)/(s − a)。若 s ≤ a，重复使用不会通过这笔账获得收益。错误损失还须另行控制，不能以更便宜的错误答案冒充效率提升。

这是成本核算恒等式，不是新定理。已经花掉的发现成本是沉没成本：它应计入研究总账，帮助决定未来预算；不能用来事后拒绝一个已经找到、此后确有价值的程序。

### 反例寻址的研究方向

程序在训练输入 x₁,…,xₘ 上的行为签名定义为：

```text
σD(p) = (p(x₁), …, p(xₘ))
```

对纯、确定性、逐点组合的语言，同一签名的程序在当前样例上可以共享搜索位置，减少重复计算。当新的反例到来时，原先相同的签名可能分开。因此必须重新搜索相关部分，或保留候选来源以重建区别。

本原型采用当前训练集合内的签名去重，以及输出残差的前缀索引。持续反例记忆、自动生成消歧问题、对程序库的自适应预算分配，是尚待实现并验证的完整架构部分。这里不把“拒绝一个候选”描述成已经掌握能够排除整类假设的约束学习。

## 三 已有理论提供什么支撑

### 压缩与泛化的标准界

设程序采用预先固定的前缀编码，L(p) 为实际编码位数，样本独立同分布，损失在 [0,1] 内。以至少 1−δ 的概率，所有候选程序同时满足：

```text
R(p) ≤ R̂(p) + sqrt((L(p) ln 2 + ln(1/δ)) / (2n))
```

证明思路是：对每个程序使用 Hoeffding 界，将失败概率分配为 δ·2^(−L(p))；前缀编码满足 Kraft 不等式，所有失败概率求和不超过 δ。这是标准压缩泛化论证，不是本研究发明的定理。

若知识库也由相同数据学习，应计入联合编码 L(M)+L(p|M)。程序节点数和代码行数可以作为复杂度代理，但没有可解码的前缀编码时，不能直接充当 L 的精确位数。本实现的 cost() 是结构偏好，不是完整 MDL 编码，也没有全局最优搜索保证。

小样本时这个界往往没有数值约束力。它解释了为什么要计入复杂度，不能替代本研究的留出实验。公开任务样例也未建立独立同分布抽样假设，故本报告不把这个界用作 73% 实测值的形式认证。[1]

### 搜索复杂度仍然存在

若每步有 b 个候选，长度上限为 d，直接枚举可能需要检查数量级为 b^d 的候选。去重、索引和复用能改变有效搜索规模，但没有由此得到任意任务都可低成本学习的结论。

复用一个长组件可能减小有效程序长度，也增加可选择组件数。收益取决于任务分布、原语、检索与错误代价。这正是本次负迁移实验测出的现实困难。

## 四 与已有研究的关系

| 工作 | 已有的重要思想 | 本研究的定位 |
| --- | --- | --- |
| MDL | 用模型与残差的描述长度选择解释 | 使用复杂度偏好；没有宣称发明压缩学习 |
| OOPS | 增量程序搜索、复用此前解、分配搜索计算 | “复用并持续求解”已有直接先例 |
| FlashFill | 从少量输入输出样例合成字符串程序 | 最接近现实用途的前例之一 |
| Euphony | 学习概率语法以指导程序搜索 | 本次仅使用公开任务数据 |
| DreamCoder | 学习程序库与神经搜索引导 | 本原型没有其神经引导或完整抽象学习 |
| Stitch | 从程序语料中高效提取共享抽象 | 本次 AST 提取远比真正的抽象发现简单 |
| Popper | 用失败产生约束，剪枝假设空间 | 本原型没有实现其逻辑约束学习 |

因此，本工作的新颖性状态是“候选组合与可检验研究问题，尚未确立学术首创”。值得继续研究的是具体的证据管理、反例索引、竞争候选和总成本控制规则，不能把已有组成部分换名后直接发表成全新智能理论。[1–7]

## 五 实际实现

核心 mechanism.py 只依赖 Python 标准库。程序使用 JSON AST 保存，解释器直接处理节点，不执行生成的 Python 源码。支持输入、字面量、字符串流水线和拼接。原语包括分段、截取、大小写、空白归一化、字符类别提取和替换。

搜索先检查简单程序，再组合能解释输出片段的候选，必要时尝试两层一元操作。行为签名合并当前样例上重复的候选；拼接搜索维护每个训练输出已经被解释的位置。前缀树减少不匹配边的尝试，最终每条边仍需在全部训练样例上检查。

默认范围：

| 项目 | 设置 |
| --- | ---: |
| 生成候选上限 | 25,000 |
| 残差匹配尝试上限 | 25,000 |
| 完整程序库检查上限 | 128 |
| 一元流水线深度 | 2 |
| 拼接片段上限 | 8 |
| 扩展中间行为上限 | 160 |
| 单个训练输入或输出长度上限 | 512 字符 |

这些是候选与匹配次数上限，不是严格 CPU 指令或墙钟预算。字符串扫描、排序、索引字符处理均有额外成本，已经包含在相应调用的墙钟计时中。推理解释器没有对任意外部 AST 提供统一 fuel 保障，当前 CLI 适用于自己生成的模型。

13 项针对真实正确性风险的测试通过，包括预算边界、已经找到的解在预算耗尽时保留、带片段数量的最短路状态、空字符串进展、索引与扫描同小型穷举解的一致性，以及 JSON 导出后重新执行。独立审阅还重放了保存的全部程序，核对预测、计数和源码哈希。

## 六 公开字符串任务的结果

### 数据与协议

数据来自 Euphony 作者仓库固定提交 0b9a62a294897b707c86ba3c0f63561ff503cb3b。下载了全部 123 个训练任务和 82 个测试任务，205 个文件逐一通过源 Git blob 校验。原始标签未被修改，训练文件内的参考解未交给学习器。[4]

测试池按预定支持范围筛选：单个字符串输入、字符串输出、至少三个不同输入、无冲突标签。82 个文件中排除 21 个非单字符串任务、12 个相同例集、9 个不足三个不同输入的任务，保留 40 个任务。这是本原型支持范围内的子集结果，不是整个测试池的成功率。

五个固定种子为 11、23、37、53、71；每次留出 max(1, floor(n/3)) 个去重例子。主指标要求同一任务划分的全部留出输出都正确。测试样例不参与候选构造或字面量发现；完整测试例对曾用于预处理阶段的精确重复排除，也用于最终评分。

协议的一个偏差需要保留：实现只去掉文件名中的 long/short/small/repeat 后缀进行分组，并检查精确例对重叠，没有达到原协议强表述的严格语义家族隔离。不同编号的电话变换任务仍跨训练和测试池出现。因此程序库迁移结果属于有限隔离条件下的探索性证据。原协议保留不改，避免事后掩盖差异。

原型采用自己的 DSL，没有遵守每个 SyGuS 文件规定的语法；以下结果是这些输入输出任务上的自定义学习实验，不是官方 SyGuS 得分，也不是 Euphony 复现或竞品速度比较。

### 主结果

| 方法 | 全部留出例正确 | 训练拟合但留出出错 | 未找到一致程序 | 累计学习耗时 |
| --- | ---: | ---: | ---: | ---: |
| 从头学习加残差索引 | 146/200 | 44/200 | 10/200 | 7.578 秒 |
| 从头学习加逐项扫描 | 146/200 | 42/200 | 12/200 | 7.646 秒 |
| 完整程序缓存加索引 | 146/200 | 44/200 | 10/200 | 7.640 秒 |
| 直接记忆训练例对 | 0/200 | 200/200 | 0/200 | 未测 |

直接记忆是低能力的诊断对照，不能据此宣布超过先进学习器。它在未见输入上没有答案；其计时未测，原始 JSON 中的零值不得解释为真实零耗时。

索引版的五次成功率为 77.5%、72.5%、72.5%、75.0%、67.5%；均值 73.0%，跨划分标准差 3.71 个百分点。40 个任务包含 34 个文件后缀分组，200 次评估存在相关性，不应当作为 200 个独立新任务计算强置信结论。

辅助指标为 1085/1140 次留出样例评估正确，即 95.18%。这些评估涉及 562 个不同输入输出对，多个种子重复评估且大任务权重更高。因此报告以 146/200 的任务划分成功率为主。

### 计算量与体积

索引减少了匹配尝试：616,638 次降到 312,671 次，减少 49.29%。但累计学习耗时仅下降约 0.89%。候选生成、字符串操作、构建索引和计时噪声仍然存在；模式采用固定顺序，未做独立随机顺序重复计时，当前没有确认实际训练显著提速。

索引版学习时间中位数为 1.565 毫秒，平均数为 37.892 毫秒。已拟合模型的推理计时，是每个留出例热循环执行 100 次后按模型汇总的中位数，约 1.277 微秒/例。它不包含进程启动、模型加载或文件 I/O。

紧凑 JSON AST 大小中位数为 42 字节，只计算程序本身，不含 Python、解释器、数据与模型封装。整个四模式基准进程峰值 RSS 为 20.125 MiB；这不是单模型内存。完整基准墙钟为 24.187 秒。

### 完整程序复用的账单

从 30 个支持范围内的源训练任务，建立 14 个通过源任务验证的程序，建库、验证与去重耗时 0.327 秒。后续 200 次学习调用耗时 7.640 秒，总计 7.967 秒；冷启动学习为 7.578 秒。计入建库后，本轮累计学习成本增加 5.13%，成功率不变。

这个结果驳回了当前简单缓存策略在本实验范围内的净收益预期，没有对所有可能的程序复用方法作出否定。

## 七 子程序复用的追加检验

在观察主实验后，另外冻结了一份探索性协议。该追加实验从实际学得的 14 个程序中提取子 AST 和流水线前缀，得到 28 个片段，紧凑序列化大小为 1,038 字节。它没有读取参考解、硬编码测试程序或改变原始主结果。

新任务先尝试由旧片段与训练目标中的常量拼接；失败后把已经消耗的候选和匹配预算扣除，再调用冷启动学习器。源库发现、片段提取和调用内验证均计入累计学习时间。

| 方法 | 全部留出例正确 | 训练拟合但留出出错 | 无解 | 含建库的累计学习耗时 |
| --- | ---: | ---: | ---: | ---: |
| 本轮从头学习 | 146/200 | 44/200 | 10/200 | 7.942 秒 |
| 本轮完整程序缓存 | 146/200 | 44/200 | 10/200 | 8.188 秒 |
| 片段复用 | 144/200 | 46/200 | 10/200 | 8.462 秒 |

片段复用出现两次额外失败，没有新增成功。它确实构造了两个不等于库内完整程序的 AST，在两个任务、不同种子下共九次通过留出；这些任务原本也能被冷启动解决。不能写成九种新能力或九个新任务。

具体失败揭示了机制问题。空白整理任务的训练例碰巧都以 The 开头，复用系统接受了“常量 The 加第二个单词”。面对：

```text
输入：    pulp   fiction
正确：pulp fiction
实际：The fiction
```

它输出了错误结果。另一次域名后缀任务接受“取最后三个字符”，面对 .uk 输出了包含点号的 .uk，而目标是 uk。旧组件解释了已有例子，但在新例子上暴露了错误假设。

下一步有依据的研究方向是：让复用候选与低成本原始候选竞争，主动寻找能区分二者的例子，并用独立的新证据决定是否晋升为可信机制。本报告没有将这些后续机制写成已实现能力。

## 八 真实表格数据的独立现实对照

另一个独立实验实现了 CostTree：使用排序、阈值比较、整数计数和标量对数的二叉规则树。叶子代价为 n log₂ n − Σₖ nₖ log₂ nₖ；分裂额外支付 α[1+log₂d+log₂(n−1)]。它属于已有贪心决策树路线，是 MDL 启发式，不是原创智能理论。

Wine 数据包含 178 条记录、13 个数值特征；WDBC 包含 569 条记录、30 个数值特征。两者均提供人工构造特征，本实验没有从原始感知输入学习表示。WDBC 仅用于历史算法基准，不是临床验证。[9–10]

五个固定种子、外部 25% 分层留出；训练集内部再分出验证集。CostTree、CART 和 100 树随机森林各使用固定八组参数，按内部验证 macro-F1 选择，再拟合完整外层训练集。测试集不参与调参。

| WDBC | CART | 92.45% ± 2.00% | 57.54 ms | 23.0 |
| WDBC | 随机森林 | 94.83% ± 2.45% | 2,302.97 ms | 2,559.2 |

整个表格实验墙钟约 21.96 秒。随机森林在两个数据集上都更准确；CART 训练更快。CostTree 展示了小型离散规则程序在有信息性的既有特征上可以获得实用预测效果，没有建立全面性能优势。这组结果也不检验字符串架构的跨任务复用。

## 九 现实用途与 WeightLang 的关系

已经可用的最小产品形态是“给例子，学习转换，导出程序”的本地 CLI。适用研究场景包括固定格式 CSV 单列整理、日志字段提取、简单名称转换与文件路径文本清洗。生成的程序可查看、可保存、可在相同规则下重复运行；遇到新格式需要新例子与重新验证。

仓库包含 examples/name_examples.json 和实际学得的 examples/name_model.json。运行：

```bash
python mechanism.py apply examples/name_model.json "Edsger Dijkstra"
```

得到：

```text
Dijkstra, Edsger
```

学习自己的例子：

```bash
python mechanism.py learn examples/name_examples.json --model learned_name.json
```

CLI 在已有目标模型路径存在时拒绝覆盖。它输出的状态为 training_consistent_only，忠实表达只有训练一致性的模型状态。44 次公开任务泛化失败说明，可靠使用仍然依赖格式范围与新的验证例子。

对 WeightLang 的可研究接口是可序列化的程序 IR、类型约束、执行预算和模型快照。当前成果是独立 Python 研究原型，没有修改 WGT 语法、Rust 执行器或宣称已经接入现有编译后端。

## 十 下一轮应满足的判据

继续研究应首先改进已经暴露的失效点，而不是扩大理论名称。

1. **竞争候选与消歧。** 在多个训练一致的解释之间保留区别；使用新证据排除偶然常量和错误位置假设。比较单候选早停、竞争候选、主动消歧的错误率与额外计算。
2. **真正的组合迁移。** 在任务级预先定义语义家族与未见组合，再冻结测试池。分别比较冷启动、完整缓存、片段复用、频次排序和成本控制，不能把重复同题的命中当成新技能。
3. **严格的生命周期成本。** 记录发现、验证、索引、内存、学习及推理；报告单次、累计与失败成本，使用随机化执行顺序和独立计时重复。
4. **拓宽能力范围。** 在另一个封闭可核验领域检验，比如状态机学习、有限环境规划或结构化程序修补。知识必须跨任务产生可靠收益，才有依据讨论更广泛智能。
5. **对照已有强方法。** 接入完整的可运行程序合成基线；在相同语法、数据和预算下比较。当前研究没有完成 FlashFill、Euphony、DreamCoder 或大型模型的公平性能对照。

超级智能还需要跨领域知识获取、长期规划、感知、行动和可靠适应的证据。本次实验没有覆盖这些能力。它交付的是可运行、可审计、可以继续被反例修正的研究起点。

## 十一 资源与证据说明

三个基准脚本的墙钟合计约 70 秒。该数字包含各自数据加载和评估流程，具体脚本口径见原始 JSON；不含数据下载、代码开发、文献检索和本轮大模型推理的计算成本。没有使用 GPU。核心字符串学习与推理只使用标准库；表格实验使用 scikit-learn 加载数据、运行对照模型与评价。

准确率标准差来自五次拆分，不是置信区间。小型公开数据、有限 DSL、人工特征、相关任务与同一环境计时限制了结论范围。原始失败案例、完整程序、预测和实验协议均保留，未按效果筛掉失败。
