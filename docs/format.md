# WGT 格式化

`wgt format` 统一 `.wgt` 源码的缩进、空格和函数体换行。`wgt fmt` 是同一命令的别名。CLI 和语言服务器共用 Rust 格式化器；以下功能描述当前仓库源码实现。

## 命令

```sh
wgt format
wgt format model.wgt modules/ops.wgt
wgt format --check
wgt fmt model.wgt
```

不指定文件时，命令从当前 WGT 项目根目录递归查找 `.wgt` 文件；没有项目配置时使用当前目录。发现过程跳过隐藏目录，以及 `weights`、`target`、`cache`、`node_modules`、`vendor`、`dist`、`build`、`dependencies`、`deps`、`venv`、`__pycache__` 和 `__pypackages__`。模型输出中的 `source.wgt` 快照保留原状。显式文件参数只处理指定的普通文件。

`--check` 不写文件；发现需要格式化的文件时打印其路径并以状态码 1 退出，全部规整时以 0 退出。CI 可以直接运行 `wgt format --check`。源码无效或读写失败时也返回非零状态，具体原因输出到标准错误。

标准输入使用 `-`，格式化结果写到标准输出，适合编辑器和命令管道：

```sh
wgt format - < model.wgt
```

`-` 不能与文件路径混用；相对导入以当前目录解析。`wgt format --check -` 只返回检查状态，不输出源码。`-C DIR` 可指定工作目录。格式化使用当前调用的可执行文件，跳过旧项目工具链版本的转发；不会下载依赖或准备 Python 环境。

## 排版规则

采用固定的 4 空格缩进。二元运算符两侧留空格，逗号后留空格；函数体中的分号和花括号形成明确的语句与块换行。命名轴、调用选项和 `init weights=xavier_uniform(7) bias=zeros()` 保持紧凑等号，`as [2, 3]`、`.T` 和切片保留原有语法。

格式化保留注释原文、字符串转义、数字字面量和声明顺序，统一源文件换行为 LF，并在文件末尾保留一个换行。它不做表达式化简或语法迁移。顶层声明仍遵守当前前端的单行边界，长参数列表不会被改成前端不支持的跨行声明；函数中已有的多行参数和数组继续分行排版。

例如，函数：

```wgt
wgt 0.5
model Identity
fn forward(x:f32[2])->f32[2]{return x;}
```

规整为：

```wgt
wgt 0.5
model Identity
fn forward(x: f32[2]) -> f32[2] {
    return x;
}
```

重复格式化不会继续改变源码。模型与算子模块在格式化前后都通过同一个原生前端检查，并核对原始 token 的内容和顺序；该过程不会初始化权重、执行 forward、训练或生成模型制品。

仓库仍支持的旧 `fn main` 模型使用相同的函数解析器及不物化权重的模型校验路径，格式化保留其现有写法。格式化不会运行宿主入口或将历史初始化写法自动升级。编辑器的容错语法夹具可能有 Rust 前端尚不接受的组合；此类文件会明确报错，不能通过格式化变成可运行程序。

命令先计算并检查所有目标文件，再开始写入，因此发现某个文件有语法或模型合同错误时，整批文件保持原状。每个改动文件通过同目录临时文件替换，未变化文件不写入。整个项目遇到后续磁盘写入错误时仍可能有此前已成功写入的文件，错误会明确报告。

## 编辑器

`wgt lsp` 提供 `textDocument/formatting`。VS Code 连接该服务后，可以执行 **Format Document** 或使用编辑器的保存时格式化设置。编辑器与 CLI 使用同一固定风格；语言服务器只返回修改建议，由编辑器应用，不自行写文件。

格式化使用当前未保存的源码，并读取已打开的本地依赖缓冲区。源码不完整或未通过检查时，返回错误并保留原内容。协议位置使用 UTF-16，CRLF 文本和非 ASCII 注释遵循相同范围规则。其他 LSP 功能和连接方法见 [语言服务器](lsp.md)。
