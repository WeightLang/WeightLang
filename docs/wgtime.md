# wgtime 统一训练与推理运行时

状态：架构合同已确定，当前 WGT 解释器仍内嵌 `weightlang-runtime`；默认 `weightc compile` / `wgt run --compiled` 已切换轻客户端后端，但仅迁移首片能力，未覆盖能力明确拒绝。全部语言、性能与资源验收尚未完成，也未发布。检查/编译不得初始化权重或执行训练。

## 库与进程边界

核心库名为 `wgtime`。`crates/wgtime` 仅含协议与轻量本地 IPC 客户端；物理独立的 `crates/wgtime-service` 才依赖现有内部执行核心，避免 Cargo feature 合并导致客户端意外链接核心。旧 `weightlang-runtime` 是迁移期内部依赖，不是最终并存的第二套运行时。编译程序负责 WGT 控制流、数据读取、HTTP、OpenResponses、工具循环和 harness。机器级唯一 wgtime 服务负责权重加载、前向、反向、参数与优化器状态、计算预算和 checkpoint。客户端不得加载权重、创建 GPU 上下文或在连接失败后回退内嵌执行。

编译器本身仍使用 `weightlang-runtime` 前端解析和生成计划；默认 AOT 产物改为仅依赖 `wgtime-control`。旧 `script::compiled` 本地支持仍供未迁移内部测试使用，不能作为轻客户端验收。编译器携带前端不等于生成程序可携带训练核心。现有 CPU 顺序模型训练、adaptive forward/loss、自定义优化器及 SAM 语义需全部迁移验证，不能把服务端训练限制为固定 loss/优化器后宣布完成。现有 gradient_snapshot 暴露参数和梯度；目标方案需在服务端执行 WGT 优化器计算，客户端仅持有控制句柄与指标，不传回梯度再上传候选参数。

## Linux 首期进程与身份合同

生产默认端点位于机器级 `/run/wgtime/`，不能依赖用户 runtime 目录、HOME 或每用户 PID。服务在监听前取得排他进程锁，持锁 FD 生命周期覆盖进程；竞争启动者明确报已运行。锁目录须由部署者安全配置，服务验证目录所有者、权限、符号链接及已有端点；不得自动夺锁、杀进程或删除不明 socket。客户端使用 Unix peer credentials 验证服务实际 UID，服务验证连接者身份；默认同 UID，跨用户服务需明确授权策略。没有安装 system service 或修改系统配置的隐式行为。

测试使用显式隔离目录与独立锁 namespace，仅证明锁和协议行为，不代表生产机器级部署完成。首期仅 Linux；其他平台明确报不支持，不使用 TCP 或内嵌回退。

## 状态、一致性与生命周期

本节及下一节描述目标合同，不表示全部已经实现。当前已有连接域句柄隔离、断连释放和部分帧长/会话/内存限制；显式 epoch/代数、覆盖全部请求的计算与内存预算、只读权重版本注册复用仍待实现。实际支持范围见“首批本地实现与剩余边界”。

目标要求每次连接拥有独立不可伪造的句柄域，服务重启生成新 epoch。连接断开/EOF 释放该连接会话与缓冲；其他连接不能引用它的句柄。所有请求有帧长、会话数、缓冲总量和计算上限，先验证再分配/执行。

首期正确性选择为每会话串行执行：推理与训练不重叠，同一更新全部候选有限性/预算检查通过后原子提交；失败保持权重、优化器矩、步数和版本。训练与推理跨会话可并行，但不得共享可变工作区、RNG 或优化器。只读模型版本按内容摘要、dtype、布局、后端及设备等完整键注册复用；可变训练会话不得通过复用键意外别名。若后续采用版本快照并行，必须计入保留版本的内存，而非宣称免费并发。

checkpoint 在服务端保存/恢复权重、优化器与步数。客户端数据游标、RNG、HTTP 与工具状态独立管理。加载模型不训练、不自动保存。路径访问必须经过身份与允许根目录校验，禁止客户端指定任意服务进程可读路径。

## 数据通道与共享缓冲

控制帧传操作、预算、句柄和标量指标；大数据走独立缓冲通道。描述符必须包含 epoch、连接 owner、槽位/代数、字节范围、shape、dtype 与读写状态。所有乘法/偏移使用 checked arithmetic；拒绝重叠越界、错误 dtype、shape、owner、旧代数和旧 epoch。

缓冲由客户端可写状态提交到服务只读状态；服务使用期间客户端不得继续写。仅协议层状态检查不足以防止恶意映射写入，须通过可验证的封印/映射权限或拷贝隔离保证。输出由服务写完后交给客户端只读，显式释放后才能复用。复用必须增加代数，旧句柄失效。磁盘大缓冲遵循 [存储合同](storage.md)，不把大型数据放 tmpfs。CPU 共享缓冲降低 IPC 复制，不承诺 GPU 零拷贝；GPU 上传、同步和回读必须真实计量。

## 编译客户端迁移矩阵

| 能力 | 最终执行位置 | 首片客户端编译范围 |
| --- | --- | --- |
| 标量/列表/记录、函数与控制流 | 客户端 | 标量/列表/函数/循环、collect/yield/size 尾批已接；其余未覆盖静态拒绝 |
| async、IO、HTTP、工具与 harness | 客户端 | 分模块迁移，禁止整脚本远程执行 |
| 模型构造/加载、推理、训练 | 服务 IPC | 客户端仅 opaque lease，禁止 Trainer/Adaptive/GPU 链接 |
| 自定义优化器/SAM | 客户端发策略控制，服务执行张量更新 | 服务注册受限策略，禁止梯度快照跨 IPC |
| agent/environment 与采集控制 | 客户端，模型计算 IPC | 随 records/环境生命周期迁移，未覆盖显式报错 |
| checkpoint/权重版本与设备 | 服务 | 已接 FD checkpoint 保存/新 session 恢复；版本共享和设备迁移待实现 |

首片是受限客户端后端，默认编译入口已切换该边界，不能称为完整语义迁移验收，也不能在不支持时回退旧执行核心。HTTP/harness dispatch 迁入 `wgtime-control`，只通过不含真实模型状态的客户端控制接口调用 IPC。

## 首批本地实现与剩余边界

新增 `wgtime`/`wgtime-service` 物理 crate 边界。Linux 服务具备连接身份检查、持锁监听、连接域句柄、顺序 CPU Adam/SGD 训练、服务内 checkpoint 快照/恢复；连接内 checkpoint 快照目前仅连接存活期间有效；持久保存/加载通过客户端授权的普通文件 FD，由服务直接编码/解码，权重字节不经客户端。保存默认原子拒覆盖，显式 overwrite 才替换普通可写文件；加载总是创建连接独立的新会话，失败不替换已有模型/优化器。自定义 [WGT 优化器/SAM 执行模块](wgtime-strategies.md) 在服务端执行受限策略字节码，梯度快照不跨 IPC；独立模块测试与真实 RPC 验收分开。统一训练 `TrainStep` 的 adaptive 路径目前使用服务端独立固定 10,000,000 操作额度，不与客户端 `max_operations` 跨 IPC 累计；策略实际返回值限制为深度最多 32、计量最多 1 MiB 的纯数据，这些边界不等于完整堆内存预算。

输入可通过 SCM_RIGHTS 传递封印 memfd，服务只读 mmap；目前仅支持 64 KiB 小型临时 f32 tensor。初始创建/write/seal/map 有真实成本，注册后复用不再发送输入 payload；这不等于初始化零拷贝。`Session::run` 仍拷贝输入到运行工作区。输出目前支持 JSON 或二进制复制；固定帧路径直接借用会话输出编码到复用响应缓冲，已移除独立输出 Vec 中转，发送前完成有限性/长度校验。输入工作区、输出编码和客户端接收的推导用户态 tensor 复制量为 `4 * (input_count + 2 * output_count)` 字节/请求，不计内核 socket 复制，仍不是零拷贝。尚未实现共享输出所有权和连续写入缓冲池。大型磁盘映射、权重版本注册复用、全进程内存预算、完整 AOT 控制层拆分、GPU 路径均未完成。

初测 release 单请求表明 JSON 和共享输入路径均未达到计算密集吞吐门槛，不能标为高性能验收通过。已有同 CPU8/单线程预算三轮顺序 CPU 基线/候选，包含微模型、256 宽模型、512 宽四层模型，推理 100 warmup/1000 samples，训练 batch8 的 10 warmup/30 完整同步 steps。推理候选尚未在全部轮次达到门槛；不得只挑通过轮次。分配插桩独立运行，基线/候选无插桩；统计含 Stats 调用，为上界，累计申请字节不是峰值活跃内存。独立 OS 进程的共同父窗口测量已保留在 `weights/wgtime-runtime-processes-20261104/`：同 CPU8 的 1/2/4 进程分别为 69,966.87 / 65,434.13 / 60,485.09 requests/s。每进程 100 warmup、10,000 请求；窗口包含 start 文件发布、200µs done 轮询及结果写入协调，属于端到端吞吐，不能当作纯服务计算吞吐。活跃连接的前后 RSS/PSS 快照不是峰值，当前各连接仍创建独立 Trainer，未实现权重共享。负载工具会监测子进程退出，失败/超时通过 RAII 杀停并回收本次子进程及临时屏障目录。

移除输出中转复制的同配置三轮对照保留在 `weights/wgtime-output-copy-baseline-20261104/` 和 `weights/wgtime-output-copy-candidate-20261104/`，均为 release、CPU8、无分配插桩，复用相同模型/输入/种子及 100 warmup/1000 samples。三轮真实服务回归均通过。512 宽四层候选相对同轮 direct 的 p50 差距为 12.07% / 7.49% / 4.54%，基线为 10.88% / 4.20% / -16.25%。direct 与固定帧测量不是相邻采样，且跨轮波动明显；负差距不能解释为 IPC 加速，当前证据仅确认复制减少，不能确认稳定延迟收益或通过性能门槛。原始日志保留 p50/p95/p99、训练及内存信息。

后续修正为相邻短块测量，原始每次耗时与块配对比保留在 `weights/wgtime-paired-output-copy-20261104/round-{1,2,3}.log`。同 CPU8/release/模型/线程预算，256 与 512 宽模型分别预热两条路径 100 次，再测 100 块，每块每路径 20 次，轮换 AB（direct 后 IPC）/BA 顺序；每块结束在计时外校验输出。三轮全部回归通过。256 宽的块耗时比 IPC/direct 中位数为 1.519 / 1.453 / 1.462，p05–p95 分别为 1.431–1.576 / 1.404–1.534 / 1.382–1.533；512 宽四层中位数为 1.084 / 1.096 / 1.078，p05–p95 为 0.943–1.227 / 0.972–1.223 / 0.915–1.270。512 模型每轮 62–67 块超过 1.05，且 AB 中位数 1.142–1.161、BA 1.008–1.031，仍有顺序效应。该比值是每块同步调用耗时总和之比；三轮均未证明达到计算密集性能门槛，不据此宣称优化带来稳定延迟收益。

分段诊断使用非默认 `latency-probe` feature 和 `tests/latency_probe.rs`，默认构建实际验证拒绝 count 高位探针。探针空输出请求仍执行身份、握手、owner、range 与输入长度校验；它只用于测往返，不能与不同输出大小的真实请求相减推导计算成本。服务从 dispatch 后记录校验/Session/有限性与编码/write 完成，排除 read、decode 和调度；write 完成不等于客户端收到。连接预分配最多 8192 条记录，满后丢弃新记录，Stats 批量取走再建缓冲。本次每组计算 2000 条、echo 1000 条，均未丢样。每次四个时钟读数及 tuple push 会扰动测量，默认构建不含这些操作。

原始成功与失败日志均保留在 `weights/wgtime-latency-segments-20261104/`。插桩 256 模型各段 p50 为 43 / 8968 / 105 / 386 ns，512 四层为 70 / 91424 / 230 / 1090 ns；分别对应校验、Session、有限性与编码、write，各段分位不可直接相加作为总分位。零输出 echo RTT p50 为 3214 / 5074 ns，服务 dispatch 后总段 p50 为 361 / 402 ns。独立未插桩诊断的 core/IPC p50 为 9008/13931 ns、98697/104348 ns；独立时间窗口差异不能直接解释为插桩成本。该 core 诊断两端用同 seed/tanh/32MiB Session、预验证一次输入有限性、逐次输出有限性检查，clone 和数值比较在计时外；原 `Trainer::predict` 用户 API 端到端基线另行保留，不被该诊断替代。目前两端推理都没有 per-call compute budget，仍是合同缺口。AB/BA 顺序效应仍存在，其 cache/调度原因未证实；RTT 与服务分段间差额仅为未归因余量。固定帧接收调用优化经协议边界检查后未实施：当前先精确读取 4 字节头，再读取当前帧长度，FD 请求的 JSON 后紧跟携带 SCM_RIGHTS 的独立单字节消息，随后专用 recvmsg 接收。客户端 API 串行等待 reply，但服务没有禁止 wire pipeline；普通 recv 最多 36 字节可能越过短 JSON 读掉附带 FD 的字节，保留字节前缀无法恢复控制消息。先读/peek 头再精确读取仍需至少两次调用；统一 recvmsg 与 FD 队列超出本轮范围，因此保留原读取路径，不据诊断宣称 syscall 已定位或性能达标。

## 性能验收

性能是完成条件。先在同硬件、模型、dtype、输入、batch、seed、线程数与后端测直接 runtime release 基线，再与服务比较。必须包含微小 CPU 单请求、计算密集模型、批量和多客户端，不能只用大 batch 隐藏 IPC 固定成本。

初始门槛：计算密集 steady-state 吞吐相对直接 runtime 回退不超过 5%；微小模型报告固定 IPC 延迟并以实际基线设定绝对预算后验收，不事后用放宽门槛代替优化。训练计算完整完成的 step，不能计异步提交时间；GPU 测试必须同步且串行协调真实设备。数值要求相同输入/种子的 loss、梯度、参数及 checkpoint 续训一致，任何差异必须解释并验证。

保留基准命令、设备与构建配置、warmup/样本数、多轮原始结果。报告冷启动、首次加载、warm 推理 p50/p95/p99、吞吐、训练 step/samples/s、RSS/PSS、峰值设备内存、显式复制字节与分配次数、多客户端扩展及共享权重/工作区复用指标。未测指标标未验证；测量波动与带宽差异说明。未达到门槛时实现尚未完成，不宣称领先其他实现。
