# wgtime 统一训练与推理运行时

状态：架构合同已确定，当前 WGT 解释器与 AOT 仍内嵌 `weightlang-runtime`。本专题中的目标合同不是已发布能力；新增服务端路径的实际验证范围须单独记录。检查/编译不得初始化权重或执行训练。

## 库与进程边界

核心库名为 `wgtime`。`crates/wgtime` 仅含协议与轻量本地 IPC 客户端；物理独立的 `crates/wgtime-service` 才依赖现有内部执行核心，避免 Cargo feature 合并导致客户端意外链接核心。旧 `weightlang-runtime` 是迁移期内部依赖，不是最终并存的第二套运行时。编译程序负责 WGT 控制流、数据读取、HTTP、OpenResponses、工具循环和 harness。机器级唯一 wgtime 服务负责权重加载、前向、反向、参数与优化器状态、计算预算和 checkpoint。客户端不得加载权重、创建 GPU 上下文或在连接失败后回退内嵌执行。

当前 AOT 的 `script_compiler.rs` 仍链接 `weightlang-runtime`，`script::compiled` 仍构造本地训练会话；新增独立客户端程序不能替代完整 AOT 边界验收。现有 CPU 顺序模型训练、adaptive forward/loss、自定义优化器及 SAM 语义需全部迁移验证，不能把服务端训练限制为固定 loss/优化器后宣布完成。现有 gradient_snapshot 暴露参数和梯度；目标方案需在服务端执行 WGT 优化器计算，客户端仅持有控制句柄与指标，不传回梯度再上传候选参数。

## Linux 首期进程与身份合同

生产默认端点位于机器级 `/run/wgtime/`，不能依赖用户 runtime 目录、HOME 或每用户 PID。服务在监听前取得排他进程锁，持锁 FD 生命周期覆盖进程；竞争启动者明确报已运行。锁目录须由部署者安全配置，服务验证目录所有者、权限、符号链接及已有端点；不得自动夺锁、杀进程或删除不明 socket。客户端使用 Unix peer credentials 验证服务实际 UID，服务验证连接者身份；默认同 UID，跨用户服务需明确授权策略。没有安装 system service 或修改系统配置的隐式行为。

测试使用显式隔离目录与独立锁 namespace，仅证明锁和协议行为，不代表生产机器级部署完成。首期仅 Linux；其他平台明确报不支持，不使用 TCP 或内嵌回退。

## 状态、一致性与生命周期

每次连接拥有独立不可伪造的句柄域，服务重启生成新 epoch。连接断开/EOF 释放该连接会话与缓冲；其他连接不能引用它的句柄。所有请求有帧长、会话数、缓冲总量和计算上限，先验证再分配/执行。

首期正确性选择为每会话串行执行：推理与训练不重叠，同一更新全部候选有限性/预算检查通过后原子提交；失败保持权重、优化器矩、步数和版本。训练与推理跨会话可并行，但不得共享可变工作区、RNG 或优化器。只读模型版本按内容摘要、dtype、布局、后端及设备等完整键注册复用；可变训练会话不得通过复用键意外别名。若后续采用版本快照并行，必须计入保留版本的内存，而非宣称免费并发。

checkpoint 在服务端保存/恢复权重、优化器与步数。客户端数据游标、RNG、HTTP 与工具状态独立管理。加载模型不训练、不自动保存。路径访问必须经过身份与允许根目录校验，禁止客户端指定任意服务进程可读路径。

## 数据通道与共享缓冲

控制帧传操作、预算、句柄和标量指标；大数据走独立缓冲通道。描述符必须包含 epoch、连接 owner、槽位/代数、字节范围、shape、dtype 与读写状态。所有乘法/偏移使用 checked arithmetic；拒绝重叠越界、错误 dtype、shape、owner、旧代数和旧 epoch。

缓冲由客户端可写状态提交到服务只读状态；服务使用期间客户端不得继续写。仅协议层状态检查不足以防止恶意映射写入，须通过可验证的封印/映射权限或拷贝隔离保证。输出由服务写完后交给客户端只读，显式释放后才能复用。复用必须增加代数，旧句柄失效。磁盘大缓冲遵循 [存储合同](storage.md)，不把大型数据放 tmpfs。CPU 共享缓冲降低 IPC 复制，不承诺 GPU 零拷贝；GPU 上传、同步和回读必须真实计量。

## 编译客户端迁移矩阵

| 能力 | 最终执行位置 | 首片客户端编译范围 |
| --- | --- | --- |
| 标量/列表/记录、函数与控制流 | 客户端 | 先标量/列表/函数/循环，其他未覆盖静态拒绝 |
| async、IO、HTTP、工具与 harness | 客户端 | 分模块迁移，禁止整脚本远程执行 |
| 模型构造/加载、推理、训练 | 服务 IPC | 客户端仅 opaque lease，禁止 Trainer/Adaptive/GPU 链接 |
| 自定义优化器/SAM | 客户端发策略控制，服务执行张量更新 | 服务注册受限策略，禁止梯度快照跨 IPC |
| agent/environment 与采集控制 | 客户端，模型计算 IPC | 随 records/环境生命周期迁移，未覆盖显式报错 |
| checkpoint/权重版本与设备 | 服务 | 首片仅连接内 snapshot；持久化与版本共享待实现 |

首片是独立的受限客户端后端，不能称为完整迁移验收，也不能在不支持时回退旧执行核心。最终公开 AOT 默认路径必须全部使用该边界。HTTP/harness dispatch 迁入 `wgtime-control`，只通过不含真实模型状态的客户端控制接口调用 IPC。

## 首批本地实现与剩余边界

新增 `wgtime`/`wgtime-service` 物理 crate 边界。Linux 服务具备连接身份检查、持锁监听、连接域句柄、顺序 CPU Adam/SGD 训练、服务内 checkpoint 快照/恢复；checkpoint 目前仅连接存活期间有效，尚无持久存储路径授权接口。自定义 [WGT 优化器/SAM 执行模块](wgtime-strategies.md) 在服务端执行受限策略字节码，梯度快照不跨 IPC；独立模块测试与真实 RPC 验收分开。

输入可通过 SCM_RIGHTS 传递封印 memfd，服务只读 mmap；目前仅支持 64 KiB 小型临时 f32 tensor。初始创建/write/seal/map 有真实成本，注册后复用不再发送输入 payload；这不等于初始化零拷贝。`Session::run` 仍拷贝输入到运行工作区。输出目前支持 JSON 或二进制复制，尚未实现共享输出所有权和连续写入缓冲池。大型磁盘映射、权重版本注册复用、全进程内存预算、完整 AOT 控制层拆分、GPU 路径均未完成。

初测 release 单请求表明 JSON 和共享输入路径均未达到计算密集吞吐门槛，不能标为高性能验收通过。现有基准只覆盖顺序 CPU、小/中模型、100 warmup/1000 samples，完整训练性能、多轮稳定性、RSS/PSS、分配/复制计数及多客户端吞吐仍须补齐。

## 性能验收

性能是完成条件。先在同硬件、模型、dtype、输入、batch、seed、线程数与后端测直接 runtime release 基线，再与服务比较。必须包含微小 CPU 单请求、计算密集模型、批量和多客户端，不能只用大 batch 隐藏 IPC 固定成本。

初始门槛：计算密集 steady-state 吞吐相对直接 runtime 回退不超过 5%；微小模型报告固定 IPC 延迟并以实际基线设定绝对预算后验收，不事后用放宽门槛代替优化。训练计算完整完成的 step，不能计异步提交时间；GPU 测试必须同步且串行协调真实设备。数值要求相同输入/种子的 loss、梯度、参数及 checkpoint 续训一致，任何差异必须解释并验证。

保留基准命令、设备与构建配置、warmup/样本数、多轮原始结果。报告冷启动、首次加载、warm 推理 p50/p95/p99、吞吐、训练 step/samples/s、RSS/PSS、峰值设备内存、显式复制字节与分配次数、多客户端扩展及共享权重/工作区复用指标。未测指标标未验证；测量波动与带宽差异说明。未达到门槛时实现尚未完成，不宣称领先其他实现。
