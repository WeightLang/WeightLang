# 模型架构表达能力覆盖矩阵（设计与验收计划）

本文是面向模型架构覆盖的设计清单，不是 WGT 语法、API 或已支持能力的承诺。矩阵中的结构都必须通过共同模型原语组合表达；不得为单个模型类别增加专用关键字。应用侧数据准备、训练循环和业务控制由 Rust 负责；WGT 模型定义拥有内部计算，实际模型计算由唯一 wgtime service 执行。当前统一状态为**尚未完成验收**，具体可用边界见[原生模型后端契约](native-backend.md)。

## 共同验收要求

每一行都要求为代表结构提供独立模型定义及最小 fixture，并逐项记录：

1. 定义解析和形状/参数 schema 检查；模型定义加载不创建实例、不初始化训练状态、不训练、不写文件。
2. 前向数值对照：固定输入、参数和 seed，与独立参考实现比较中间及最终张量；覆盖边界形状、数值稳定性和非法输入。
3. 梯度对照：对全部可训练参数及输入检查解析梯度，并以中心有限差分复核；覆盖共享参数、冻结参数和分支路径。
4. 训练与事务：至少一个明确优化器/损失的真实训练任务；核验 loss 变化、有限参数、失败时原子性及重复运行的确定性范围。
5. 状态恢复：区分模型定义、初始化实例、权重、优化器状态和 checkpoint；保存、关闭、恢复后比较前向及后续更新。没有状态的类别仍需证明无需伪造状态恢复能力。
6. Rust 与编译运行路径：Rust 主程序控制数据/循环；通过 wgtime service 验证；若有编译客户端，还须单独验证生成程序。不得以 parser 成功、旧 core 路径、GPU 自动跳过或训练指标单项替代完整验收。

当前只有 MLP 可作为既有 facade / service backend 的局部基线；仍未完成此矩阵要求的全部前向、梯度、训练和状态恢复验收，编译客户端路径也待测。其余类别一律标为未验收。GPU、混合精度、多输入/批量接口、缓存及跨进程状态共享须按实际合同另行标注，不能由架构名称推断支持。

## 逐类覆盖矩阵

| ResNet | 两个残差块和投影捷径 | 线性/卷积、归一化、激活、同形加法 | identity/projection shortcut；残差两支梯度与形状对齐 | 未验收 |
| DenseNet | 两个稠密块及过渡层 | 特征拼接、卷积/线性、归一化、激活 | 拼接轴、通道增长、跨层梯度与内存边界 | 未验收 |
| CNN 1D | 多通道序列卷积与池化 | 1D 卷积、padding/stride、局部归约 | 长度边界、因果/非因果设定、输入和 kernel 梯度 | 未验收 |

## 验收记录规则

每类只有在代表 fixture 的定义检查、前向数值、梯度、真实服务训练和相应状态恢复均有可复现本地证据后，才能把状态从未验收改为已验收。新增原语时优先验证共同原语及组合，不用类别名称或宏包装替代计算实现。编译客户端、GPU、性能、跨后端恢复分别记录，不从 CPU facade 结果外推。历史/目标设计必须标注来源和状态，不以此表扩展现行语言语法。
