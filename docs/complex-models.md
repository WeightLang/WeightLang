# Native complex-model primitives

These interfaces are implemented in the current source tree, not a new published release. WGT source version remains 0.5; all four instructions require Adaptive IR v3. The shared Rust frontend validates source and serialized plans. Rust/wgtime executes native CPU kernels with bounded workspace and a reverse-mode tape. They currently use interpreter fallback instead of AOT C or GPU kernels. Python selects the native service by default; explicit `backend="torch"` uses FX or ordinary Torch modules according to the program.

| Signature | Contract | Gradient |
| --- | --- | --- |
| `gelu(x)` | f32 tensor, rank 1..8, unchanged shape and named axes. Exact `x/2*(1+erf(x/sqrt(2)))`, no approximation mode. | Analytic derivative on x. |
| `topk_mask(x,count)` | f32 tensor, rank 1..8; count is f32[1], finite exact integer 0..last-axis width. Returns same-shaped 0/1 selection mask independently on every last-axis row. Ties prefer lower indices. | None through selection or count; a subsequent multiplication retains value gradients. |
| `masked_softmax(x,mask,axis)` | Same-shaped f32 logits and strict binary mask; no broadcasting. Axis is an in-range nonnegative integer literal or named axis. Every axis group needs a valid element. | Ordinary softmax VJP on logits, exactly zero at masked positions; no mask VJP. |

All arguments are required. Tensor shapes follow existing 1..8-rank, register-element and service-port limits; successful compilation does not bypass session memory or execution budgets. Input/parameter values must satisfy the existing finite-f32 contract. Masked normalization computes its maximum over valid positions only and accumulates exponentials in f64, so a large invalid logit cannot underflow the valid group. Empty groups, nonbinary masks, fractional/negative/oversized counts fail before a successful transaction commit. Top-k uses bounded scratch space and charges the last-axis selection search to execution work. It does not make ties follow unspecified PyTorch top-k ordering.

The complete example [complex_routing/model.wgt](../examples/native_training/complex_routing/model.wgt) applies exact GELU, masks padding, and selects probabilities. It contains no trainable parameters or implicit initialization. `topk_mask` selects up to count positions, including zero-valued masked probabilities when count exceeds the number of valid positions; the returned probabilities at those positions stay zero.

Native CPU/VJP, invalid inputs, ties, work-budget checks and Torch differential tests live in `crates/wgtime-core/tests/complex_primitives.rs` and `python/tests/test_complex_primitives.py`. LightNest additionally verifies restored full ELF/H-Net generators, notebook compression and three attention modes against its original Torch implementations, including native parameter updates. That application validation does not establish arbitrary Python-model translation, universal dynamic batching or deployment performance.

Large declared parameters can be read directly with an explicit shape, for example `embedding(table as [257,128],ids)`. This uses the existing Read IR with the requested same-element-count shape, avoiding an invalid intermediate flat axis of 32896 elements. An ordinary bare parameter read retains its legacy flat-vector contract; it does not relax tensor-axis, element, port or memory limits. The service still validates parameter storage independently, and index gradients remain zero while selected rows receive scatter-add gradients. The explicit-read path is exercised with a >16384-element table in the native core tests and the default-width LightNest generators.

## Stateless dropout

`dropout(x,rng,probability)` preserves the f32 tensor shape and named axes (rank1..8). All three arguments are required. `rng` is f32[4]: `[seed_low16,seed_high16,stream16,training]`. The first three values must be exact integers in0..65535; training must be0 or1. Probability is a finite numeric literal represented as f32 in[0,1); it has no default or gradient. Eval or probability0 is identity, but configuration validation and work charging still apply.

This is explicit, deterministic input data, not mutable global RNG. The host chooses a fresh seed/stream when it wants a fresh training mask. Forward and VJP use the identical configuration, so backward never draws another mask. Only x receives gradients; RNG has none. There is no implicit seed advance, service RNG state, or compatibility promise with PyTorch's global random sequence. Existing transaction rules and typed no-autograd execution remain unchanged. Work costs1 plus the element count, with the usual enclosing instruction/loop costs. Rust currently uses CPU interpreter fallback; the same WGT runs through explicit Torch FX/program execution. Torch host batches can supply one shared configuration or a configuration per sample; counters restart per sample's declared tensor geometry.

The counter is row-major flat index i. Combine seed=`low | high<<16`, then uint32 wrapping `z=seed ^ (stream*0x9e3779b9) ^ (i*0x85ebca6b)`. Apply `z^=z>>16; z*=0x7feb352d; z^=z>>15; z*=0x846ca68b; z^=z>>16`, wrapping every multiply to32 bits. Uniform=`(z>>8)/16777216`. Keep when uniform>=probability and scale by f32 `1/(1-probability)`; otherwise output zero. See [explicit_dropout/model.wgt](../examples/native_training/explicit_dropout/model.wgt) and native/Python differential tests in complex_primitives.
