# WeightLang 设计理念：优雅描述模型内部架构，让架构决策成为可学习参数

> **WeightLang 的愿景，是让模型架构可读、可组合、可学习、可编译：WGT 优雅表达模型内部，Rust 清晰控制模型外部，标准库承载可复用计算。**

架构定义不只是权重的容器，也可以成为可审阅、可复现、可优化的设计对象。工程师能从定义中理解计算如何组成，由 Rust 稳定地准备数据和控制实验，再把冻结的模型交给统一执行服务。

> **实现状态：** 可学习架构参数（Learnable Architecture Parameters）的浮点、有界浮点、严格正域、有界整数与布尔声明已在本地实现，并通过定点训练、原生编译前向和服务权重重载测试。完整语法及 STE 代理梯度规则见[可学习架构参数](learnable-architecture-parameters.md)。本文的 `choice`、自动 `repeat` 和状态组合仍是设计方向；当前架构范围见[原生后端契约](native-backend.md)与[架构覆盖验收矩阵](architecture-coverage.md)。

## 职责边界

- **WGT 描述模型内部。** 模型定义表达固定结构、张量形状、前向计算、可选的可微损失，以及明确声明的状态读写。模型局部计算可由标准库提供可组合模块；模块复用计算，不隐式创建模型实例、训练状态或副作用。
- **Rust 控制模型外部。** Rust 应用负责读取和准备数据、批次与采样、训练循环、指标和业务策略、资源生命周期及服务连接。应用显式请求初始化、推理、更新、加载或保存；模型定义的解析本身不执行这些动作。
- **唯一 wgtime service 执行模型计算。** 应用通过客户端持有连接与实例句柄，不自行链接第二份执行核心。模型定义、实例、权重、优化器状态与 checkpoint 是分离对象。当前实现边界以[原生后端契约](native-backend.md)为准。

这种拆分让一份模型定义既可独立审阅，也可嵌入 Rust 产品；标准库模块可以组合复用，而应用仍使用成熟的 Rust 工具管理数据、训练实验和服务生命周期。

## 定义、实例与状态

设计上区分以下概念，具体语法和 API 需以实际实现为准：

- **`const`：固定结构或普通常量。** 适用于模型宽度、层数、卷积核尺寸等编译/解析期结构信息，以及不会训练更新的数值。固定结构参数决定张量 shape，不能在普通梯度更新中任意改变。
- **`parameter`：模型中的可训练张量。** 它有确定的名称和 shape，初始化、冻结状态及权重由显式实例生命周期管理。标准优化器更新的是这些张量的数值，不会自动改变模型图或张量尺寸。
- **`learn`：可学习的架构决策。** 当前本地实现包含浮点数、严格正域、有界整数与布尔值；每种类型都有明确的合法域、更新规则和读取行为。有限 `choice` 仍是提案，下面混合展示已实现声明与未来方向：

```wgt
# 以下三项已在本地实现，须置于完整模型定义中。
learn depth: int in 1..=12 = 6;
learn use_skip: bool = true;
learn temperature: float > 0.0 = 1.0;
# 未来提案，当前解析器拒绝：
# learn activation: choice {relu, tanh, gelu} = gelu;
```

这里的值描述候选架构决策及其约束，不是参数张量声明。浮点温度可以连续优化；深度、开关与 activation choice 则需要离散搜索策略，或经明确定义的松弛/估计方法。

- **`input`：一次调用显式提供的数据。** 输入值、批次大小、序列长度等运行数据不是全局架构参数。当前 facade 首期只承诺单个固定宽度 f32 向量输入；多输入、变长序列、缓存和动态 shape 不因愿景而自动可用。
- **`state`：跨步或跨调用保留的运行状态。** recurrent hidden state、memory slot、随机状态及训练器状态需要各自明确的所有者、读写边界、重置和恢复规则。状态不能因定义复制而共享，也不能在模型加载时隐式创建或持久化。

模型定义解析是纯操作：校验结构与接口并产生可复用定义值。Rust 应用随后显式创建服务实例、选择初始化或绑定权重，并控制推理和训练。定义、实例与制品的边界让每个阶段都可独立审阅、测试与复现。

## 让 RecurrentBlock 的结构参与学习

下面用一个短循环块展示愿景：WGT 表达模型内部的共享 cell，架构决策选择深度和是否加入 skip；Rust 仍负责提供序列、发起训练和评估。代码是**设计示意，不是可执行语法**，其中 `learn`、`repeat`、`state` 与 cell 接口均未承诺为现行 API：

```wgt
# 仅为设计示意，当前不可执行
model RecurrentBlock
input x: f32[features]
output y: f32[features]
learn depth: int in 1..=12 = 6;
learn use_skip: bool = true;

state hidden: f32[features]
fn forward(x) {
    let h = repeat depth {
        cell(x, hidden)
    };
    if use_skip { return h + x; }
    return h;
}
```

`depth` 和 `use_skip` 决定结构候选，`hidden` 是实例运行状态，`x` 是一次调用的输入，cell 的共享权重则是普通 `parameter`。硬化某个候选后，需要按最终深度和分支结构冻结定义、校验 shape、重新编译，再绑定对应权重或 checkpoint；切换候选不能假装是同一固定 shape 实例内的普通数值更新。

## 架构学习的离散边界

浮点权重可用普通反向传播；架构候选则可能含离散 choice、开关、整数深度和拓扑变化，它们需要与普通权重不同的优化方法。可选路线包括：

1. **连续松弛（relaxation）**：训练期间对多个候选做加权组合。它通常增加激活、计算与显存成本，而且软组合目标与最终硬化后的结构可能有差距。
2. **Straight-Through Estimator（STE）**：前向采用离散选择，反向使用代理梯度。它减少软组合语义差异，但梯度是估计量，必须测量偏差、稳定性和任务效果。
3. **非梯度搜索**：Rust 外部控制候选采样、进化或其他搜索，将每个候选编译/实例化后评估。它容易保持离散语义，但可能需要大量训练与验证成本。

这些是待评估的设计选项。架构决策的验收需要同时衡量搜索成本、离散估计的限制，以及训练候选硬化为真实结构后的效果差异。

## 固定结构、编译与存储

首期模型定义以固定 shape 和可验证的参数 schema 为基础。学习到会改变静态图或 shape 的层宽、层数、分支或模块选择后，应将候选硬化为明确架构，再重新验证并编译定义；每个实例仍对应确定的结构。

冻结后的架构定义、初始化说明、权重与运行/训练状态应分别存储或引用：

- 定义记录结构、接口和初始化声明，不携带训练实例或优化器历史。
- 权重记录与已冻结定义兼容的张量值；shape/name 匹配不能单独证明计算语义兼容。
- checkpoint 按明确格式保存所支持的权重及训练状态；权重文件与完整训练恢复材料各自承担清晰职责。
- 若架构搜索需要复现，应显式保留候选定义、搜索算法与配置、随机种子、候选评估数据/结果、冻结后的定义和对应 checkpoint。恢复时先校验定义与权重 schema，再由应用明确创建或恢复实例。

## 可组合模型结构

WGT 模型以共同的张量与状态原语组合 MLP、残差、卷积、注意力、循环、专家路由和图计算等结构。标准库将可复用计算封装成模块，并公开形状、状态、梯度与版本契约；组合结构由简洁的模型定义表达。

逐类代表架构、需要的计算原语以及前向数值、梯度、训练和状态恢复验收，见[模型架构覆盖矩阵](architecture-coverage.md)。当前统一状态是未验收；只有矩阵中确有本地 facade/service MLP 基线的局部证据，不代表完整模型覆盖、编译客户端、GPU 或性能已通过。
