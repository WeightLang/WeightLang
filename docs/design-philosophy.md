# WeightLang 设计理念：显式表达模型参数、状态与计算规则

> **WeightLang 的愿景，是让模型的参数、状态，以及计算和更新它们的规则可读、可组合、可审阅。** WGT 描述模型内部，Rust 应用负责外部数据与调度，唯一的 `wgtime` 服务持有可变模型实例；可复用算法通过标准库显式导入。

模型不必总是一个必须执行前向、计算 loss、反向传播的网络。梯度训练是可选的模型使用方式；模型也可以通过具名操作演化状态，或接受外部生成的参数候选。定义、实例、参数、状态和更新规则应有清晰边界，实际能力则以各自实现和验收状态为准。

> **实现状态：** [模型组合与可学习控制](model-composition.md)记录了 WGT 0.5 本地实现及其验证范围，包括 `learn` 声明、混合、条件、有界 `repeat` 和子模型实例数组；尚未发布，验证范围不代表任意动态控制流或完整模型覆盖。[多范式模型操作](model-operations.md)记录多入口、状态事务、外部参数候选和显式 `train_with_policy` 的本地 core 与真实 service 通过情况，当前尚未发布；具体合同与验证细节以该文档为准。`choice` 仍未实现。下文区分本地已验证能力与发布状态。

## 职责与所有权

- **WGT 描述模型内部。** 模型定义可包含参数 schema、状态 schema，以及显式的计算和更新规则。模型可选择提供 `forward`、可微 `loss` 和梯度训练路径；这些不是所有模型必须具备的结构。
- **Rust 应用控制模型外部。** Rust 负责数据准备、I/O、训练或搜索循环、指标、业务策略、资源生命周期和服务连接，并显式调度模型操作。无论采用梯度训练还是外部搜索，调度均由应用负责。
- **唯一 `wgtime` 服务拥有可变模型实例。** 服务持有实例的参数和状态，并执行经授权的计算与更新。Rust 应用通过客户端句柄发起调用，不持有另一份可变执行核心。
- **算法通过标准库显式导入。** Loss、attention、block、求解算法等可复用计算应通过明确的 `import` 使用；不依赖隐式预导入 preset，也不把算法选择藏在模型定义之外的神奇默认值中。

模型定义的解析不应隐式创建实例、执行操作、训练或生成制品。实例初始化、参数绑定、状态创建与重置，以及权重或 checkpoint 的保存和恢复，都是显式生命周期操作。普通权重与运行状态、含优化器状态的 checkpoint 各自有明确含义；保存权重不能暗示状态也被保存。

## 参数、状态与规则

模型中的关键对象各有不同职责：

- **固定结构与常量**描述 shape、模块组织或不参与更新的值。改变静态结构或 shape 的候选需要按相应规则验证并生成兼容定义，不能当作普通张量数值更新处理。
- **参数**是模型可读取或更新的数值，具有名称、shape、合法域及初始化或绑定规则。参数可以由已验收的梯度训练路径更新，也可以在显式合同下接收外部搜索产生的候选。
- **状态**是实例持有、可跨操作保留的运行数据。它由明确的状态 schema、读写规则、隔离、重置和恢复语义管理；状态不是普通权重的别名。
- **计算与更新规则**规定输入如何影响输出、参数候选如何产生或验证，以及状态和参数何时发生变化。规则应可审阅，副作用应显式。

`learn` 表示受约束的可学习值声明，不将该值永久绑定到某一种优化策略。旧 forward 训练路径提供 `ContinuousOnly` 与 `StraightThrough` 策略；其中学习条件的既有旧 `train` 行为使用 STE。显式策略接口 `train_with_policy` 已在本地 core 与真实 service 通过，但尚未发布。typed operations 不使用 AD 或 optimizer；其参数候选更新遵循显式操作与事务合同。各路径的详细合同见[多范式模型操作](model-operations.md)。

当前可学习控制的语法、数据域和实证范围见[模型组合与可学习控制](model-composition.md)。例如，已实现有界重复：

```wgt
learn depth: int in 0..=8 = 2;

fn forward(x) {
    # 每轮接收并返回同形状向量；具体展开和学习深度规则见实现文档。
    return repeat depth carrying h=x { block(h) };
}
```

这段仅用于展示当前文档中描述的可学习深度与 `repeat` 组合，不声称它独立覆盖所有训练或运行时路径。`choice` 仍是未实现的设计方向，不能把它写成当前可用语法。

## 多范式计算与更新

前向计算、loss 和 backprop 是一种有用的组合，不是模型概念的边界。模型可以有 forward 和可微 loss，并由应用启动梯度训练；也可以暴露不依赖 loss 或 backprop 的操作，用来读取和更新实例状态，或应用外部搜索得出的参数候选。

[多范式模型操作](model-operations.md)记录了多个具名、typed 操作，显式状态写入和事务候选、失败时无更新，以及经校验后显式提交参数候选的合同与验证细节。这些能力的 core 与真实 service 已在本地通过，尚未发布。typed operations 不使用 AD 或 optimizer；其参数候选路径由显式操作处理。该合同明确首期不支持跨状态求导。

无论更新来自梯度优化器、状态操作还是外部候选，都需要明确更新对象、合法性校验、提交边界、失败语义及实例隔离。具体规则属于对应的实现合同；理念文档不为尚未冻结的语法或 API 补造细节。

## 组合与标准库

WGT 通过张量与状态原语组合模型内部结构。当前已验收范围和局限见[模型组合与可学习控制](model-composition.md)：其中包括受约束的混合与条件、固定上界的重复、子模型定义及独立实例数组。它们的本地验证不应被扩大解释为任意控制流、任意 shape、多输入、任意 dtype 或完整架构覆盖。

可复用算法和模块放在标准库中，并由模型显式导入。每个模块应公布实际实现的签名、输入输出 shape、参数和状态行为及版本限制。模型组合复用计算，不应隐式创建实例、训练状态或副作用。

## 冻结、存储与复现

若候选改变静态图或 shape，应根据实际定义合同硬化并重新验证、编译，再绑定兼容参数。对固定结构中的参数或状态候选，则按相应操作合同验证和提交；两类变化不能混作同一种更新。

为复现模型和实验，应按职责分别保存定义、参数权重、训练 checkpoint、运行状态（仅在持久化合同明确后）、候选生成规则与配置、随机种子及评估结果。定义加载不应隐式初始化实例；权重不自动携带运行状态；形状和名称相符也不能单独证明语义兼容。

## 验证状态与边界

判断能力状态，应区分本地实现与验证、发布状态和适用范围。当前证据及限制分别见[模型组合与可学习控制](model-composition.md)和[多范式模型操作](model-operations.md)：两者记录本地实现及其验证边界，均不代表已发布，也不应扩展为文档未验收的能力。

Rust 应用持续负责数据、I/O 和外部调度；`wgtime` 是可变模型实例的唯一 owner。模型可以选择梯度训练，也可以采用其他具有明确合同的更新路径。文档中的愿景或设计草稿不等同于解析器、运行时、服务或发布能力。
