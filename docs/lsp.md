# WeightLang 语言服务器

`wgt lsp` 在编辑 `.wgt` 文件时提供函数参数提示、张量形状、模型参数量和原生编译诊断。编辑器通过标准输入/输出与它交换 LSP 消息；语法与形状检查复用 WeightLang 的 Rust 前端，不启动 `wgtime` 服务、不初始化权重或执行模型。

本文描述当前仓库源码的功能。使用时需要包含 `lsp` 子命令的 `wgt`，以及对应的编辑器客户端；源码构建与 Marketplace、工具链 Release 的发布状态分别管理。

## 安装与启动

在仓库根目录安装当前源码的命令行工具：

```sh
cargo install --path crates/wgt --bin wgt --locked
wgt lsp --help
```

`wgt lsp` 是供编辑器启动的长期运行进程，直接在终端运行时会等待协议消息。它使用当前调用的可执行文件，跳过项目固定工具链的转发和依赖准备；项目中的旧版本固定配置不会让编辑器服务退回旧二进制。更新服务版本时，更新编辑器实际调用的 `wgt`。

### VS Code 与兼容扩展的编辑器

从仓库构建本地 VSIX：

```sh
cd editors/vscode
npm ci
npm test
npm run package
```

在编辑器执行 **Extensions: Install from VSIX**，选择生成的 `weightlang-0.2.0.vsix`。打开可信工作区中的 `.wgt` 文件后，扩展会启动 `wgt lsp`。完整构建说明见 [BUILD.md](../editors/vscode/BUILD.md)；该操作不会发布扩展。

如果编辑器的 `PATH` 找不到 `wgt`，设置可执行文件的绝对路径：

```json
{
  "weightlang.server.path": "/absolute/path/to/wgt",
  "weightlang.server.enabled": true
}
```

`weightlang.server.path` 只填写可执行文件路径，扩展会添加 `lsp` 参数。远程工作区使用远程扩展宿主上的可执行文件。修改路径会自动重启；替换二进制后可执行 **WeightLang: Restart Language Server**。将 `weightlang.server.enabled` 设为 `false` 可关闭服务，TextMate 高亮、注释切换和括号配对继续可用。受限工作区仅启用这些静态编辑功能。

### 其他 LSP 客户端

Neovim、Emacs/Eglot 或其他支持 LSP 的编辑器可按各自客户端的配置格式注册：

| 配置项 | 值 |
| --- | --- |
| 可执行文件 | `wgt`，或其绝对路径 |
| 参数数组 | `["lsp"]` |
| 传输方式 | stdio |
| 语言标识 | `wgt` |
| 文件扩展名 | `.wgt` |

服务支持标准 LSP 初始化、文档同步和下表中的请求。各编辑器的语法高亮安装方式见[编辑器支持](editors.md)。Zed 仓库扩展目前提供 Tree-sitter 集成，其 manifest 尚未接入此语言服务器。

## 编辑时能看到什么

| 功能 | 使用方式与结果 |
| --- | --- |
| 函数签名 | 输入 `(`、`,` 或手动触发参数提示，查看参数列表与当前实参；嵌套函数和形状数组中的逗号不会被误算为外层参数 |
| 参数名称提示 | 在调用实参旁显示对应参数名；实参名称已经与形参相同时省略重复提示 |
| 张量形状 | 悬停查看已检查的绑定形状、命名轴及元素数；省略类型注解的局部绑定可显示行内形状 |
| 模型参数量 | 悬停模型名称查看总参数元素数、可训练元素数、冻结元素数及状态元素数；模型声明旁显示总量 |
| 原生诊断 | 检查语法、调用参数数量、矩阵乘法、reshape、命名轴和模型合同；问题修复后清除旧诊断 |
| 补全 | 提供当前可见声明、适用的内置入口、导入模块函数和张量后缀 |
| 导航 | 定义跳转、当前文件引用与引用高亮；直接导入的本地函数可跳到其源文件 |
| 重命名 | 对当前文件中可解析的声明和引用生成修改，检查遮蔽、名称冲突和模型合同 |
| 结构与颜色 | 文档大纲、已打开文件的符号搜索、花括号块折叠及语义高亮 |
| 快速修复 | 为缺少或不受支持的版本头提供 `wgt 0.5` 修改建议 |
| 格式化 | **Format Document** 调用与 `wgt format` 相同的 Rust 排版实现，统一 4 空格缩进、运算符空格和函数换行；无效源码保持原状 |

VS Code 将诊断显示在 Problems 面板与源码下划线中。行内提示由编辑器的 **Editor: Inlay Hints** 设置控制；参数弹窗也可通过 **Trigger Parameter Hints** 手动打开。颜色遵循当前主题。

格式化通过 `textDocument/formatting` 返回整份文档的修改建议，使用未保存文本及已打开的本地依赖。编辑器负责应用修改或保存；服务不自行写文件。源码已经规整时返回空修改列表。命令、固定风格与 CI 检查见 [WGT 格式化](format.md)。

## 形状与参数量示例

将下面的模型保存为独立目录中的 `model.wgt`：

```wgt
wgt 0.5
model MatrixProjection

# 每行权重产生一个输出，三列分别对应三个输入特征。
parameter weight: f32[2,3] = [1, 0, 0, 0, 1, 0]
frozen bias: f32[2] = [0, 0]
state ticks: f32[1] = [0];

fn forward(input: f32[3]) -> f32[2] {
    # 参数读取为扁平向量；as 指定本次计算使用的矩阵形状。
    # 命名轴放在 let 类型注解中，收缩轴 features 必须兼容。
    let w: f32[outputs=2, features=3] = weight as [2, 3];
    let x: f32[features=3, batch=1] = input as [3, 1];
    let y = w @ x;
    return (y as [2]) + bias;
}
```

检查通过后，`w` 的形状为 `f32[outputs=2, features=3]`，`x` 为 `f32[features=3, batch=1]`，`y` 推断为 `f32[outputs=2, batch=1]`。矩阵乘法将两侧大小为 3 的 `features` 轴配对，保留输出轴和 batch 轴；这里的 `batch=1` 是静态轴名称与长度，不增加宿主动态 batch 行为。

`weight` 包含 6 个参数元素，`bias` 包含 2 个冻结参数元素，因此模型显示 **8 个参数元素：6 个可训练、2 个冻结**。`ticks` 的 1 个状态元素单独统计。`forward` 接受 **1 个函数实参**：函数实参数量与模型存储参数量分别显示。

当前多轴参数读取为扁平向量，所以 `weight` 的存储布局为 `f32[2,3]`，读取值为 `f32[6]`。悬停会同时解释存储布局和读取形状。`as [2, 3]` 给读取值赋予矩阵形状；它只接受正整数数值维度，命名轴仍写在 `let` 类型注解中。完整规则见[张量几何](tensor-geometry.md)。

### 看懂形状错误

将示例中 `x` 的声明改成下面这一行，会得到矩阵乘法维度诊断：

```wgt
let x: f32[batch=1, features=3] = input as [1, 3];
```

此时 `w @ x` 的两侧为 `[2,3]` 和 `[1,3]`：左矩阵有 3 列，右矩阵实际只有 1 行，收缩维度要求 3、实际为 1。把 `x` 恢复为 `[3,1]` 后，原生检查重新计算形状并清除错误。

把 `weight as [2,3]` 改为 `weight as [2,2]` 则违反元素总数约束：原有 6 个元素，目标形状只容纳 4 个。LSP 使用与 `wgt check model.wgt` 相同的模型合同报告这类问题；不自动添加广播、补零或截断。

## 检查范围

**中间张量形状与模型统计在原生模型验证成功后提供。** 正在输入或尚有错误的文件仍可获得词法补全、签名、导航和诊断；错误修复前不会保留上个版本的形状作为当前结果。诊断采用原生前端当前返回的首个错误，修复后继续检查下一个问题。

打开文件的未保存文本参与分析。直接本地导入的补全、签名和定义跳转使用相应文件的已打开缓冲区；模型检查也会使用已打开依赖的文本。VS Code 监听本地 `.wgt` 文件变化，保存、外部修改和关闭依赖缓冲区都会触发相关的重新检查。`std/` 函数签名与说明来自工具链内嵌标准库，无需下载。

引用与重命名限定当前文件，工作区符号搜索限定已打开文件。重命名会跳过注释、字符串、属性名和形状轴标签，拒绝名称冲突、未完成的结构、无法完整解析的成员改名，以及需要同步导入者的导出算子函数改名。对原本检查通过的模型，候选修改还会重新经过模型合同检查。

诊断位置按编译器可提供的信息定位。普通操作与绑定有源码行信息；子模型展开后的错误可能定位到根模型声明，并在消息中保留具体原因。它不提供任意 Python/PyTorch 程序的形状推断，也不验证运行时输入数值、训练结果或硬件行为。单个打开文件的分析上限为 1 MiB，最多同时跟踪 64 个文件。

## 排查启动问题

| 现象 | 处理 |
| --- | --- |
| 提示未知 `lsp` 子命令 | 安装包含该命令的源码版本，检查编辑器实际调用的 `weightlang.server.path` |
| `ENOENT` 或找不到可执行文件 | 配置绝对路径；远程工作区确认远程宿主上也存在该文件 |
| 只有高亮，没有诊断 | 检查工作区信任、`weightlang.server.enabled` 和 **Output → WeightLang Language Server** |
| 有诊断但没有中间形状 | 先修复 Problems 中的原生模型错误；形状只在检查成功后显示 |
| 更新二进制后仍使用原会话 | 执行 **WeightLang: Restart Language Server** |

协议实现见 [`crates/wgt/src/lsp/`](../crates/wgt/src/lsp/)，语义分析入口见 [`crates/wgt-language/src/ide.rs`](../crates/wgt-language/src/ide.rs)。维护者应对照 [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/) 保持 UTF-16 位置、增量修改顺序和诊断清理语义，并复用原生前端的类型与形状合同。
